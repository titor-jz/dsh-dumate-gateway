## V1 — DSH client 插件的右侧栏注册方式：**可做，契约已拿到**

### 证据来源

1. `@deepseek-ai/dsh-client-ui-sidebar-right@0.2.2-rc.3` 的 `README.md`（167 行）：两段式注册（类型 + 渲染体）都在各自的 `ctx.effect` 里；`ctx.sidebarRight` 是导航控制器；body 通过框架注入的 `useTabInfo()` 拿 `{sidebar, panel, tab}`；已知限制「**无会话就没有右侧栏**」（state 按 sessionId 存 `dsh.sidebar-right.v1.<sessionId>`）。
2. 同包 `package.json`：`dsh.client = { platform: 'web', inject: [7 个包 id] }`，无 `immediately`。
3. **三个真实扩展包的 `lib/client.js`（最强的证据，直接可抄）**：
   - `dsh-client-ui-sidebar-documentpreview`（README 自称"the live proof"）
   - `dsh-client-ui-sidebar-files` / `-terminal` / `-browser`
   它们都是：module 级 `exports.apply / exports.inject` + `window.__ModuleLoader__.load({ id, factory })`，注册类型用 `ctx.sidebarRightTabs.register(...)`，body 用 `ctx.slots.inject('sidebar.right.pane.tab', () => ctx.slots.register({ name, key, locale, store, inject, children }, Body))`，标题位同 key 注册 `sidebar.right.pane.tab.title`。
4. live client 的 `cordis_inspect_query`：client 侧 8 个 Service（`layout` / `locale` / `sessions` / `slots` / `theme` / `timer` / `uiWorkspace` / `workspaces`）；slot 树里确认 `sidebar.right.pane.tab`（keyed，**当前无人占用**，keyDomain 开放）、`sidebar.right.pane.tab.title`（keyed，同上）、`sidebar.right.tab.guide`（chain）、`sidebar.right.tab.guide.entry`（keyed）、`sidebar.right.tab.guide.actions`（list）、`sidebar.right.tab.menu.item`（list）、`sidebar.footer.action`（list, root）、`conversation.session.header.utilities`（list, session）。
5. 打开/收起面板的 layout 动作：`ctx.layout.openRightbar(track: boolean, fullscreen: boolean)`、`ctx.layout.closeRightbar()`。

### 可照抄的骨架（v1 侧栏就用这个）

```jsonc
// package.json 片段
{
  "name": "<新包名>",
  "exports": { ".": "./lib/index.js", "./client": "./lib/client.js" },
  "dsh": {
    "client": {
      "platform": "web",
      "inject": ["@deepseek-ai/dsh-client-ui-sidebar-right"]
    }
  }
}
```

```js
// lib/client.js
window.__ModuleLoader__.load({ id: '<包名>', factory: (require) => {
  const module = { exports: {} }; const exports = module.exports;
  const inject = ['slots', 'locale', 'sidebarRight', 'sidebarRightTabs', 'theme'];

  function apply(ctx) {
    const t = ctx.locale.bind('llmGateway');
    ctx.effect(() => ctx.locale.register('llmGateway', { zh, en }), 'llm-gateway: i18n');

    // ① 类型（page 型：不写 patterns，用 kind 打开）
    ctx.effect(() => ctx.sidebarRightTabs.register({
      id: '<包名>',            // 全局唯一，重复注册会 throw
      kind: 'llmGateway',
      priority: 'extension',   // builtin | extension | fallback
      keepMounted: true,
      title: () => t('title'),
      guide: [{                // 右侧栏空态/引导页里的入口卡片
        id: 'llmGateway', order: 40,
        title: () => t('guide.title'),
        description: () => t('guide.description'),
        icon: /* primitives 里的某个 artwork */,
      }],
    }), 'llm-gateway: type');

    // ② 渲染体
    ctx.effect(() => ctx.slots.inject('sidebar.right.pane.tab', () => ctx.slots.register({
      name: 'sidebar.right.pane.tab', key: '<包名>', locale: 'llmGateway', store,
      inject: (sessionId, actions) => ({ /* 面板需要的 face */ }),
    }, GatewayPanel)), 'llm-gateway: body');

    // ③ 标题位（可选；不注册则用开 tab 时快照的 title）
    ctx.effect(() => ctx.slots.inject('sidebar.right.pane.tab.title', () => ctx.slots.register(
      { name: 'sidebar.right.pane.tab.title', key: '<包名>' }, GatewayTitle)), 'llm-gateway: title');
  }

  exports.apply = apply; exports.inject = inject;
  return module.exports;
}});
```

入口（建议三个都给，至少给前两个）：

- guide 卡片（`guide: [{...}]`）：右侧栏引导页自动出现，点开即 `openTab`；
- 一个按钮：`sidebar.footer.action`（list, root）或 `conversation.session.header.utilities`（list, session）→ `ctx.sidebarRight.openTab('llmGateway')`（需要 `sidebarRight` 服务）；
- 快捷键：`ctx.shortcuts.register({ id: 'llmGateway.open', label, aliases, defaults })`。

### 对设计文档的 3 处校正（已回填 spec §10.1 / §17 / §19）

1. **§10「单页，三段」不够**：还缺「入口」和「无会话」两个情形。右侧栏是 session 作用域，**没有选中会话时右侧栏根本不存在**（官方 Known Limitation）——所以 (a) 面板必须靠 guide 卡片或按钮主动打开，(b) 「没会话时也想看网关状态」需要另给一个 `main` 面板或设置页区块，不能只靠侧栏。
2. **§4.1 的 `client/index.js` 单文件不够**：client 半区必须是完整插件模块（`dsh.client` + `exports['./client']` + module 级 `exports.inject` 服务键 + `__ModuleLoader__.load`），文件放在 `lib/client.js`（或任意 `./client` 导出指向的文件）。
3. **两类 inject 不是一回事**：`package.json` 的 `dsh.client.inject` 列**包 id**（插件依赖，等对方插件加载）；`lib/client.js` 的 `exports.inject` 列**服务键**（`slots`、`locale`、`sidebarRight`、`sidebarRightTabs`、`theme`…）。两者都要写，写错一边就是 `ctx.xxx undefined`。

### 一个仍未验证的点（不影响可行性，P6 首日解决）

**client 半区怎么读到 host 半区的实时状态**（上游列表、在线点、延迟、模型表）。两条候选：

- **A（建议）直连本地 HTTP 网关**：面板 `fetch('http://127.0.0.1:7321/health')` 与 `/v1/models`。零新增 API 面，本来 P5 就要做这两个端点；需要网关侧 CORS 放行 GUI 源、以及页面 CSP 的 `connect-src` 不拦。CSP 未实测（GUI 走 401 鉴权，`curl -I` 看不到页面头，得在浏览器里实测）。
- **B 走 DSH 的 client `remote` 服务**定义 host RPC（documentpreview 就是这么读文件的）。作为 `gateway.http.enabled=false` 时的兜底。

结论：**V1 通过**，P6 可做；A 方案让侧栏几乎不依赖新增后端接口。

## P1/M2/M3 实现记录（2026-11-15 深夜）

从「继续」开工，落地骨架 + 真实发现 + A 面转发，全部 node 级真机 e2e 通过（细节与文件清单见 plan §12）。

**新增事实（写代码时才暴露的）**

1. **DSH 要求模型目录 id 唯一**（`listModels` 校验，重复抛 `INVALID_CATALOG`）。DuMate 目录 43 个键里 `glm-5` 与 `model-text` 都指向 id `model-text` → 42 个唯一 id。解法：自名项（`model-text`）保留 id，别名项改用键名（`glm-5`，实测上游同样 200），43 条一条不丢。`src/upstream/discovery.js` 里两遍分配。

## 面板 `Failed to fetch`：改走 host 同源 Fetch 路由（2026-11-16 00:1x）

**现象**：引导页修好、面板能渲染后，内容区报 `The gateway is not reachable at http://127.0.0.1:7321… Failed to fetch`。

**排除**：网关本身正常 —— `curl http://127.0.0.1:7321/health` → `models:16`；`netstat` 有 `127.0.0.1:7321 LISTENING 22864`；带 `Origin: http://127.0.0.1:14203` 请求返回 `access-control-allow-origin: http://127.0.0.1:14203` + `vary: origin`；`src/gateway/server.js` 的 `cors()` 只反射 loopback 源（`isLoopbackOrigin` 认 127.0.0.1/localhost/::1）。页面级 CSP 在包里也找不到（只有 media / plugin-detail 的 `sandbox; default-src 'none'`）。

**结论**：页面侧跨源限制（GUI 可能不是 loopback 页面 / 页面策略直接拒），不是网关 bug。**插件面板不能依赖跨源 fetch。**

**受支持路径**：host `connection` 服务的 Fetch 路由（`cordis_inspect_query(host, Service, listService)` 里可见）：

```js
ctx.inject(['connection'], inner => {
  inner.effect(() => inner.connection.fetch.register({
    path: '/dumate-gateway/status',   // 位于 /api 之下 → 浏览器打 /api/dumate-gateway/status
    methods: ['GET'],
    requestBody: 'buffered',
    fetch: statusResponse(reader),
  }), 'dumate-gateway: status route')
})
```

契约：`path` 在 `/api` 之下；`methods: ('GET'|'HEAD'|'POST')[]`；`requestBody: 'buffered'|'streaming'`；「Only owner Peers reach an exact route; the shared handler answers 403 for every other principal」。参考实现：`@deepseek-ai/dsh-deepseek-chat-import/lib/index.js`（上传路由）、`dsh-client-ui-deliverables`（`/api/changes.summary` 等）。

**实现**：
- 新 `src/host/status-route.js`：`STATUS_PATH='/dumate-gateway/status'`、`createStatusReader({version, modelsMode, modelsExclude, catalog, reachable})`、`statusResponse(reader)`；catalog 抛错 → `offline()` 带 `reason`（面板显示「启动 DuMate」空态而不是报错）。
- `index.js`：`ctx.inject(['connection'], …)` 注册（`connection` 是可选服务，不写进 `inject` 数组）。
- `client.js`：`load()` 先 `fetch('/api/dumate-gateway/status')`，失败才回退 `GATEWAY/health` + `/v1/models`；错误文案改成「两个通道都没拿到」。
- 测试：新增 `test/status-route.mjs`（payload/离线/参数透传/no-store）+ `test/plugin-host.mjs`（apply 注册 1 个 adapter + 1 条 route、`http.enabled:false` 不启网关、disposer 收尾）。

**教训**（与上一条并列）：client 侧一切「本地服务」请求都走 host 注入的同源路由，不要直连端口；跨源在桌面 GUI/远程 GUI 下都可能被静默拒绝，且错误只有 `Failed to fetch`，无法定位。

## Today 柱状图重做（2026-11-16 15:05-15:15）

**反馈**（m01978）：「today 板块树状图展示部分还是有点丑，这里再改改」。

**三代形态与取舍**：
1. 单根柱 + 基线（初版，viewBox 300×72）：7 天里 6 天没数据，只剩 6 根 2px 短柱，看起来像「七根孤零零的标签」。
2. 堆叠柱（input 在下浅色 / output 在上实色）：柱底很浅、像「浮在轴上」；上下两段有接缝，读起来像一块色块而不是两个量。
3. **成对细柱（采用）**：每天两根圆角柱（宽度 `min(8, slot*0.2)`），input 浅（今天 0.4 / 其余 0.2）、output 实（今天 1 / 其余 0.48），都从基线起算；空天只画 `height:2` 的 tick（opacity 0.18）坐在轴上；今天一根淡色圆角带（opacity 0.06，从柱顶上方 18px 包到基线下方 4px）同时框住柱子与数值标签。

**测试**：`test/client-plugin.mjs` 空账本时断言 `rect` 共 8 个（1 个今天带 + 7 个 tick）、`height===2` 的恰好 7 个。

**验证**：刷新页面即生效（客户端半区从磁盘读）；实测 `Today 314 tokens · in 106 · out 208`，Mon 两根柱（input 浅 / output 实）、Tue–Sun 六个 tick，标签 `314` 落在今天带内。截图更新到 `docs/assets/sidebar-panel.png`（77726 B）。

**教训**：多日小图里「空天」应该是轴上的刻度而不是 0 高柱；成对柱比堆叠柱更容易读出 in/out 比例，也不会出现「浅色底部像悬空」的错觉。
